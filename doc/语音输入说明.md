# 语音输入说明

- 日期：2026-10-25
- 方式：长按空格键说话，松开出字；按住时上滑超过一个按键高度再松开则取消
- 引擎：sherpa-onnx 1.13.8（`yuyansdk/libs/sherpa-onnx-1.13.8.aar`），完全离线
- 模型：SenseVoice int8 2024-07-17（约 239 MB，支持普通话、英语、粤语、日语、韩语）

## 怎么装模型（不用数据线）

设置 → 输入法 → **语音识别**：

1. 用手机浏览器下载两个文件（页面上有链接，可直接点）：
   - https://hf-mirror.com/csukuangfj/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17/resolve/main/model.int8.onnx （约 228 MB）
   - https://hf-mirror.com/csukuangfj/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17/resolve/main/tokens.txt
   - hf-mirror.com 是 huggingface.co 的国内镜像；这两个文件和测试用的模型逐字节一致（哈希已核对）
2. 点“导入模型文件”，在系统文件选择器里同时选中两个文件（长按第一个再点第二个），点“选择”
3. 页面显示“已安装（228 MB）”即可使用；页面上也能删除模型

导入是先复制到临时文件再改名，中途失败不会留下半个模型；文件名不像模型（不是 `.onnx` 或 `tokens*.txt`）、或 `.onnx` 小于 50 MB（可能没下载完）会跳过并提示。
App 没有申请网络权限，导入走系统文件选择器，输入法仍然完全离线。

## 模型放在哪

手机上的路径：`Android/data/<包名>/files/sensevoice/`，里面放 `model.int8.onnx` 和 `tokens.txt`。
电脑上的备份：`models/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17/`

用 adb 推送时，**目标路径要写到完整文件名**，否则 Windows 版 adb 遇到源路径里的中文会截断文件名：

```
adb push <模型目录>/model.int8.onnx /sdcard/Android/data/<包名>/files/sensevoice/model.int8.onnx
adb push <模型目录>/tokens.txt /sdcard/Android/data/<包名>/files/sensevoice/tokens.txt
```

调试版包名是 `com.yuyan.pinyin.offline.debug`。

## 为什么选 2024-07-17 而不是更新的 2025-09-09

在电脑上用官方 sherpa-onnx 对同一段音频做了对比：

| 音频 | 2025-09-09 | 2024-07-17 |
|---|---|---|
| 普通话 | 放时间早上九点至下午五点（无标点、数字不转换、丢字） | 开饭时间早上9点至下午5点。 |
| 英语 | THE TRIVBAL CHIEF THIN … OF COOOD | The tribal chieftain called for the boy and presented him with 50 pieces of code. |

## 实测数据（模拟器）

- 首次加载模型约 2-3 秒（按下麦克风时开始加载，和说话同时进行）
- 模型加载后，识别 7 秒音频约 1.1 秒
- 静音保护：最响的一帧音量低于 0.01 时不识别，提示"没有听清"（模型对静音会凭空识别出"我。"这类字）

## 已知限制 / 待办

- 模型常驻输入法进程内存（约 250 MB 级），真机上需要观察内存占用
- 调试版额外打包了 x86_64，只为在模拟器里跑；正式版只有 arm64
- 静音阈值 0.01 需要在真机上根据日志 `VoiceInput: ... peak rms=` 校准
- 真机上的识别速度、真实说话效果还没测（模拟器没法真的说话，识别准确率是用模型自带的测试音频验证的）
- 调试版有一个测试入口：`adb shell am broadcast -n <包名>/com.yuyan.imemodule.voice.VoiceDebugReceiver --es wav <wav路径>`，结果在 logcat 标签 `VoiceDebug`
